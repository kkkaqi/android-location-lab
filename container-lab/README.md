# 容器微信定位 0.2.3

这是独立的免 Root 容器实验应用，已从启动/登录验证扩展到容器内微信专用定位。坐标修改与关闭均通过容器自己的配置和访客进程适配，不修改容器外应用。

- 应用包名：`app.containerlab`，与定点和原微信独立。
- ARM64；编译 SDK 35。为保留引擎对旧版 API 的兼容方式，min/target SDK 为 28；不是面向应用商店的生产版本。
- 保留上游来源、固定提交及 Apache-2.0 LICENSE；见 UPSTREAM.md。
- 核心编译成功也不能证明 Android 15／ColorOS 15／当前微信版本实际兼容。

## 手机测试

1. 保留手机原有微信，安装本实验应用。
2. 打开“容器启动测试”，先查看是否出现引擎初始化错误。
3. 点击“导入本机已安装的微信”，等待容器安装记录确认；失败则复制诊断。
4. 点击“请求启动容器内微信”，观察是否实际出现微信启动或登录页。
5. 返回测试应用，点击“复制精简诊断”，反馈所见页面和错误。复制文本最多1600字符，优先保留最近错误；第一阶段以启动/登录页面为验收点，不需要在此阶段输入账号凭据。

容器实例不迁移原微信登录状态、聊天记录或账号数据。成功发出启动请求不是微信已成功运行；上游可能退回创建基本 Application，因此诊断会显示实际类名，并避免把回调当作微信初始化成功。

## 已处理的上游行为

自动崩溃日志上传已从源码移除；关闭公共 Downloads 日志采集及日志清空、VPN、守护服务、可选 Root 隐藏等设置。诊断只写入应用私有存储，用户主动复制时才进入剪贴板。引擎拦截失效时不会主动退回打开原微信，以免误判。

上游携带的 Dobby 静态库仍为预编译输入，没有独立审计其机器码。此原型没有经过完整的安全审核或真机兼容性验证。

## 构建

需要 Python 3.9+、JDK 17+、Gradle 8.14.3、Android SDK 35 / Build Tools 35、NDK r28c。

```powershell
python .\tools\bootstrap_container.py
powershell -NoProfile -ExecutionPolicy Bypass -File .\container-lab\test.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\build-container.ps1 -GradleHome C:\path\to\gradle-8.14.3
```

从主项目根目录运行。构建脚本将源码和局部 SDK 复制到用户目录 `.codex/build-cache/fixed-location-container/` 的英文路径，以避开 Windows AIDL／NDK 的中文路径问题；不修改全局 JDK 或 SDK 设置。

编译输出位于该缓存项目的 `app/build/outputs/apk/debug/app-debug.apk`。最终交付 APK 必须另外通过签名和 ARM64 打包检查。

运行 `python tools/package_container.py` 执行签名、ARM64 ELF 和归属信息检查，并按 APK 实际版本生成主项目 dist 下的安装包及独立源码包。初版验证见 VERIFICATION.md，0.1.1补丁依据与测试边界见 VERIFICATION-0.1.1.md。

## 0.1.1 网页权限兼容测试

覆盖安装，保留原有容器数据。升级后重新启动容器内微信，从微信正常登录流程重新产生安全检查页面；旧网页与旧 ticket 不作为复测入口。这个版本修正正常联网权限查询的身份对应，没有改写安全检查网页、服务器响应、证书验证或账号登录结果。

若仍失败，复制诊断，重点检查访客 Context 的 INTERNET 与 ACCESS_NETWORK_STATE 是否为0。附错误码即可，不要粘贴完整登录 ticket、验证码或手机号。不能把0视为登录成功，只代表该权限查询获得系统允许。

## 0.1.2 手机精简诊断

覆盖安装即可，版本号3，同一包名和签名。只改变诊断显示和复制，不修改引擎运行、权限映射或微信数据。

- 屏幕和剪贴板共用最多1600字符的摘要，不再复制全部启动流水。
- 显示本次宿主运行的导入/启动记录、进程回调次数和每个进程最近的两项联网权限结果。
- 最近两条不同异常优先显示，保留最深层原因和首个访客/容器堆栈；早于本次宿主启动的异常标为历史。
- 上次导入的微信版本可作为带标签的历史版本信息保留；重复的成功初始化记录合并。
- 完整原始记录仍在原有私有日志文件中，原有容量轮转规则不变。导出前继续脱敏登录参数。
- 没有新增原生崩溃、系统退出记录或微信内部异常采集；“未记录到异常”不能证明没有崩溃。

## 0.1.3 系统退出诊断

点击“刷新诊断”或“复制精简诊断”时，在宿主后台线程读取自己包的 Android 退出历史，最多读取32条，优先显示最近两条非更新、非人工停止的记录。若只有人工停止记录则显示一条，仍标为历史。所有记录都需按时间核对，不自动视为本次微信故障。

若选中记录为原生崩溃，并且系统仍保留可读 tombstone，读取最多4MiB，按 AOSP Android15 schema 提取信号、abort消息及故障线程少量栈信息；不导出内存、完整日志、其他线程、命令行。不可读、过大或格式异常会明确注明。系统环形缓冲可能没有保留记录；空结果不证明没有退出。

复制仍最多1600字符，优先放系统证据，再放已有私有日志摘要。系统字段也在截短前脱敏。此版增加取证，不修改微信运行逻辑、不删除数据、不新增系统权限或自动上传。覆盖安装，启动微信复现一次，马上返回宿主复制诊断；不要反复尝试登录或清除数据以替代采证据。

官方接口与格式：[ActivityManager](https://developer.android.com/reference/android/app/ActivityManager#getHistoricalProcessExitReasons(java.lang.String,%20int,%20int))、[ApplicationExitInfo](https://developer.android.com/reference/android/app/ApplicationExitInfo#getTraceInputStream())、[AOSP Android15 tombstone.proto](https://android.googlesource.com/platform/system/core/+/refs/tags/android-15.0.0_r1/debuggerd/proto/tombstone.proto)。

## 0.1.4 退出前异常观察

针对reason1/status1且普通处理器无记录的情况，在访客进程安装 Android15 异常预处理观察器，先本地记录再转交原预处理器。保留原 Throwable 身份及系统处理行为，不拦截 exit、不吞异常；若隐藏接口不可用，会记“预处理观察：不可用”，不阻止微信启动。

复制诊断时，针对最新选中的主动退出或Java崩溃记录，由宿主读取自己真实UID的main/crash错误日志快照（最多400条、64000字符尾缓冲、2.5秒进程等待）。仅输出与退出PID匹配且处于退出前30秒至后3秒的错误摘要，优先深层异常及业务栈。不可读/超时明确注明。历史PID可能复用，因此时间也必须匹配；跨年时间比较尚不支持。

保留数据覆盖安装，启动容器微信复现一次，马上返回复制诊断。此版本仍是查因，不承诺已修复启动退出。

## 0.1.5 登录后应用语言查询修复

USB/JDI定位到聊天预加载函数内的应用语言读取抛出 READ_APP_SPECIFIC_LOCALES SecurityException。宿主UID使用访客包名访问原微信的语言配置，被系统判为跨应用查询，随后聊天View未创建，最终表现为setVisibility空指针。

新增SDK33+ locale服务代理：只对绑定的微信虚拟user0读取自身语言时，将参数包名映射到真实宿主，继续调用原系统服务。读取的是独立宿主的应用语言配置；没有修改原微信设置、语言写入接口、系统授权或账号数据。其他包/用户/未知签名保持原调用。安装包沿用原签名，覆盖安装保留数据。

## 0.2.0 容器微信定位

输入WGS84纬度/经度，点击“启用并重启容器微信”。默认武汉30.595000/114.297500。只保存微信包名、虚拟用户0的独立位置配置；首次默认关闭，启用前申请宿主普通前台精确位置权限。按钮会重启容器微信以清除旧定位监听/缓存，保留数据与登录。点击“关闭并重启容器微信”清除启用状态并重新请求正常位置。

Android15的最近位置、单次位置、持续监听、PendingIntent及取消回调由访客进程内适配器处理，生成带当前墙钟和单调时钟的位置。持续监听约每秒更新一次，取消/死亡/关闭时停止。新版List/IRemoteCallback与旧Location回调分开处理，不走上游旧版监听线程。启动后的“访客定位核验”只是框架接口回读与回调检查，不能作为微信或小程序采纳的证明。

微信初始化后可能重建定位服务包装，因此适配器在访客 Application 初始化完成后连接到当前框架服务，保留原有委托。微信/user0 的网络及位置权限查询委托系统查询实际宿主授权；未授予的后台位置仍返回拒绝。精简诊断只保留最近一次框架核验结论，重启或修改配置后旧结论失效。其他已缓存的 Context 或后续重建服务仍需通过实际页面验证覆盖情况。

不调用Android test-provider，不设置全局模拟位置、不改容器外微信或地图、网络/IP。IP归属地与通过其他网络路径得到的位置不属于本功能保证；微信/小程序是否采用需实机观察。原有的系统模拟定位软件设置保持用户当前状态。

## 0.2.1–0.2.2 网页兼容调查

修复空 Service 启动 Intent 的解析崩溃；恢复访客 Activity 时保留原目标请求，恢复失败不再无限入队。增加仅限调试构建的固定 USB 网页自检，使用有明确测试标识的本地 HTML，不运行登录或验证。

0.2.2 针对 OnePlus/OPPO Android15 容器内微信的 XWeb 沙箱子进程，改用系统默认的可选帧调度实现，避免已观察到的 OEM 帧加速 ioctl 与渲染沙箱冲突。只改变该访客进程的缓存和现有主线程编舞器；不改变系统、原微信或 Chromium 沙箱。真实扫码登录与小程序定位是否可用仍以真机复测为准。
