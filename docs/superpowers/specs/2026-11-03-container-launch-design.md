# 独立微信容器启动验证

用户已确认接受独立实例及重新登录，先验证导入、启动微信，再考虑定位。

## 已排除的候选

pengliangAndroid/VirtualLocation 固定提交 fedfd4c549062e126e0a81c50da94a247c47e9ad：构建 SDK/target 25，native 配置仅 armeabi-v7a/x86；仓库自带 APK 的核心 libva++.so 仅存在于 lib/x86。README 另有 VirtualApp 个人研究限制。该项目只作本地研究，不直接合并或重签分发。

## 本次方案

- 独立应用“容器启动测试”，独立包名，不修改已有定点、系统设置、原微信 APK 或原微信数据。
- 候选引擎 TeguFy/blackbox-android，固定提交 bf1623b7d45157bbc87be46a29352dd6bbbde9fa。保留 Apache-2.0 LICENSE、各文件声明与修改记录。
- ARM64 首发。仅导入本机已安装的 com.tencent.mm 到容器 user 0，不下载未知来源微信，不复制账号数据或自动登录。
- 页面：引擎状态、已安装微信版本/架构、导入、请求启动、复制诊断。报告启动请求与“实际页面可用”之间的区别。
- 不接入定位篡改、身份变更、Root 隐藏、VPN、外挂模块等额外功能。
- 初始化/导入/启动异常明确记录；提供用户主动复制的设备与应用错误诊断，无自动上传。

## 验收

本机可验证：核心输入/架构判断、编译、ARM64 native 打包、签名、包名与 manifest。
用户手机必须验证：安装独立原型、引擎初始化、导入微信、实际看到微信启动/登录页、退出与再启动。编译通过不视为微信兼容性通过。
