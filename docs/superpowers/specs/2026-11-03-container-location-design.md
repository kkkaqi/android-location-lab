# Container-only WeChat location

User explicitly authorizes location modification inside the container, leaving outside apps untouched. Reuse saved target Wuhan30.595000/114.297500 as editable defaults. UI provides latitude/longitude validation, enable and disable, each followed by a virtual-WeChat-only restart to clear preexisting real listeners/caches while preserving data/login. Default is disabled; persist own-package/user0 configuration through the existing internal location service, never global mode or Android test providers.

Guest hook handles Android15 last location, current location, continuous listener callbacks and pending intents, provider queries and removal. It only supplies coordinates when a bound WeChat/user0 has OWN_MODE and a valid configured location. Other apps/users/modes delegate normally. Cancellable local scheduled subscriptions send fresh timestamped positions approximately once per second; remove/death/disable stops delivery without busy loops. Modern list callbacks and nullable completion callback follow AOSP Android15 signatures. No root, location-setting changes, network/VPN changes or modifications to installed outside WeChat.

Enable requests ordinary host foreground location permission so WeChat's checks can work. Direct core calls verify saved config rather than trusting wrappers that swallow failures. An internal guest framework readback distinguishes delivery from WeChat adoption. Device acceptance requires an actual WeChat location page (no message or attendance submission), plus confirmation that the outside original app/system test-provider setup is not changed. IP/network-derived or app-specific positioning may require further work; do not claim coverage without observation.
